# 08: Data repo and publisher tooling

Spec: `.scratch/hardening-c-fast-fix/spec.md` (Hosting and publishing). ADR-0006.

**What to build:** A separate data repo where Gamedata is edited through PRs.

- **Layout:** snapshots per `SourceRevision` and OS.
- **Python publisher** (`cryptography` package, grown from ticket 03's signer):
  - builds the index from the snapshots (size, sha256, `patchVersion`)
  - increments `seq` from the last published index
  - signs with the domain-separation prefix and key id
  - refuses snapshots that are not valid Gamedata JSON or exceed the caps
- **Publish workflow:** a GitHub Action that runs on merge to main in a protected environment, runs the publisher and deploys index, signature and snapshots to the host. All third-party actions are pinned by commit SHA.
- **Seed:** today's bundled Gamedata as the first snapshot for the current build.

Until ticket 09 this uses a test key and a dry-run target.

**Blocked by:** 03

**Status:** ready-for-agent

**Tier:** 2 add-on · must

- [ ] Publisher unit tests: `seq` increments; deterministic index bytes for the same input; oversized or invalid snapshots refused
- [ ] Cross-implementation fixtures generated by the publisher are checked into the native tests and verify there; mutated ones fail
- [ ] Workflow runs in dry-run mode on a PR (builds and signs with the test key, no deploy) and every action is SHA-pinned (a lint step fails otherwise)
- [ ] README in the data repo: how to edit a snapshot, add a kill, and what a merge publishes
